# Антифрод: поток транзакций, скоринг и переобучение

Проект обнаружения мошеннических транзакций. Kafka несtт поток событий, CatBoost скорит их текущей моделью, а Airflow поставляет размеченные месяцы, переобучает модель с quality gate и публикует отдельный Data Quality отчет.

| Сервис | Описание |
|--------|----------|
| **Kafka** | Шина сообщений между симулятором потока, скорингом и записью результатов |
| **Zookeeper** | Управление кластером Kafka |
| **Kafka UI** | Просмотр топиков `transactions` и `scoring` |
| **transaction_simulator** | Шлет случайные строки CSV с новым ID и текущим временем. Исправлено поле `target`: удаляется до публикации, метка обучения не раскрывается скореру.|
| **fraud_detector** | Препроцессинг и инференс CatBoost. Перед каждым сообщением читает `/models/latest.txt` и подхватывает `my_catboost_<версия>.cbm` без перезапуска |
| **scoring_writer** | Читает топик `scoring` и пишет `score`, `fraud_flag` и `model_version` в PostgreSQL |
| **PostgreSQL** | Витрина `labeled_transactions`, состояние окна `training_state` и таблица `scores` |
| **data_loader** | При старте один раз загружает весь CSV в витрину и собирает исходное окно обучения: январь–март 2019 |
| **airflow** | DAG поставки, переобучения и проверки Data Quality; расписание — каждые 5 минут |

Общий том `model_registry` смонтирован в Airflow как `/opt/airflow/models` и в `fraud_detector` как `/models`. Логика задач вынесена в `pipeline/`. Файлы в `dags/` только связывают задачи.

Модельный каталог и `/opt/airflow/reports` — отдельные именованные тома. Каталог `/opt/airflow/models` и хранит HTML-отчеты DQ.

## Работа проекта

1. `data_loader` копирует `TRAIN_DATA_CSV` в `labeled_transactions` и сохраняет окно января–марта 2019. Повторный старт без `down -v` витрину не перезаливает.
2. `transaction_simulator` каждые 0.1 секунды отправляет в Kafka случайную транзакцию с текущим временем.
3. `fraud_detector` скорит поток моделью из общего каталога. До первого переобучения версия — `initial`: в каталог копируется модель из образа.
4. `scoring_writer` складывает результат в `scores`, включая `model_version`.
5. DAG `supply_labeled_batch` каждые 5 минут берет из витрины 100 тысяч случайных строк, переносит их время в следующий календарный месяц и дописывает батч. Наблюдения старше трех лет относительно самого нового месяца удаляются.
6. DAG `retrain_catboost` каждые 5 минут забирает следующий месяц, сдвигает трехмесячное окно и делит его по времени (два ранних месяца — train, свежий — test). Собственный препроцессинг создает циклические признаки времени, логарифм суммы и разницы координат.
7. Кандидат проходит quality gate: ROC-AUC должен быть не ниже текущей production-модели; F1 не должен упасть более чем на 0.01. При ухудшении публикация пропускается, `latest.txt`, `current.parquet` и указатель месяца остаются прежними. Для стартовой модели без сохраненных метрик первый кандидат принимается.
8. DAG `data_quality` проверяет витрину и сохраняет HTML-отчет в `/opt/airflow/reports`.

Переобучение и поставка идут по разным указателям месяца. `retrain_catboost` читает исторические месяцы с апреля 2019. `supply_labeled_batch` каждый раз создает месяц после максимальной даты витрины, первый такой месяц — апрель 2020. Окно обучения еще долго не доходит до этих батчей, и очистка трех лет его не затрагивает.

Оба DAG можно запустить вручную в Airflow, не дожидаясь расписания. Если очередного месяца в витрине еще нет, задачи переобучения помечаются как skipped.

## Как запустить проект


### Создать `.env` файл

```bash
cp .env.example .env
```

В `TRAIN_DATA_CSV` укажите путь к `train.csv`.

### Запуск контейнеров

```bash
docker compose up --build
```

### Очистка

```bash
`docker compose down -v`
```

## Примечания

1. В Kafka UI топик `transactions` пополняется каждые 0.1 секунды, топик `scoring` — ответами модели.
2. В Airflow будут `supply_labeled_batch`, `retrain_catboost` и `data_quality`. Кнопка Trigger запускает DAG сразу.
3. У `retrain_catboost` интересны `check_model_quality` и `publish_model`. При отклоненном кандидате задача gate станет `skipped`, модель и ее версия не изменятся.
4. После публикации модели новые сообщения в `scores` получают свежий `model_version`.
5. Можно посмотреть отчеты `docker compose exec airflow ls -la /opt/airflow/reports`. Скопировать HTML к себе `docker compose cp airflow:/opt/airflow/reports/<имя-файла> ./<имя-файла>.html`.

## Quality gate: сравнение моделей

Сравнение выполняется на одном и том же типе временного среза: свежий месяц — test, более ранние месяцы — train. Основная метрика — ROC-AUC, она должна быть не ниже значения текущей модели. F1 при фиксированном пороге 0.5 может снизиться не более чем на 0.01, чтобы небольшое колебание не блокировало обновление. Метрики версии лежат рядом с файлом модели в `my_catboost_<version>.metrics.json`. Если начальная модель из образа еще не имеет файла метрик, первый обученный кандидат принимается как baseline.

Gate не двигает указатель месяца при отклонении, чтобы не терять неуспешно проверенный батч. Поэтому повторные запуски снова проверят этот месяц. для продвижения потребуется улучшить кандидата/изменить критерий либо вручную обработать состояние после анализа метрик.

## Data Quality правила

`data_quality` проверяет таблицу `labeled_transactions`. Каждая строка отчета содержит число нарушений (для правила наличия данных — число строк):

1. В таблице есть данные.
2. `transaction_time` не пустой.
3. `target` не пустой.
4. `target` принадлежит множеству `{0, 1}`.
5. `amount` неотрицательный.
6. Координаты клиента заполнены и находятся в допустимых диапазонах широты `[-90, 90]` и долготы `[-180, 180]`.
7. Координаты продавца заполнены и находятся в тех же диапазонах.
8. `cat_id` заполнен и не является пустой строкой.

HTML отчет записывается в `/opt/airflow/reports/data_quality_<UTC timestamp>.html`. Проверки читают агрегаты SQL, а не всю таблицу в память. Airflow запускает DAG по расписанию, отчет также можно получить ручным Trigger.

## Итого главные изменения

Сделано на основе кода с семинара.

1. **Устранена утечка метки в онлайн-поток.** `transaction_simulator` исключает `target` из `data` перед отправкой в Kafka. Онлайн-препроцессор также удаляет `target`, если поле случайно пришло во входе. Метка остается в таблице и нужна только для обучения.
2. **Добавлен собственный feature engineering.** В `fraud_detector/src/preprocessing.py` добавлены циклические признаки часа, день недели, логарифм суммы, разницы координат и географическое расстояние. Эта же функция используется при обучении и онлайн-скоринге, чтобы схема признаков совпадала. Базовые календарные и географические признаки сохранены.
3. **В DAG переобучения добавлен quality gate.** Перед публикацией кандидат сравнивается с текущей моделью по временной test-выборке. ROC-AUC должен быть не ниже production baseline. F1 при пороге 0.5 может снизиться максимум на `0.01`. При провале gate публикация и сдвиг окна не выполняются. Если у стартовой модели еще нет файла метрик, первый кандидат принимается как baseline.
4. **Добавлен отдельный `data_quality` DAG.** Он выполняет SQL-агрегаты по размеченной витрине и публикует HTML-отчет в `/opt/airflow/reports`
